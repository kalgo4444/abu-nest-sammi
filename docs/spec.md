# Product spec

Abu Nest Journal: a small blog ("journal") where anyone can create, read, edit, and delete text entries. A NestJS API stores entries in MongoDB and a Next.js site is the only client.

This spec describes the behaviour the code implements today. Places where that behaviour is probably not what a finished product wants are listed under [Known gaps](#known-gaps). For setup and conventions, see [index.md](./index.md).

## Requirements

### Functional

1. List all entries on the home page.
2. Filter the list by a search term.
3. View one entry in full.
4. Create an entry.
5. Edit an existing entry.
6. Delete an entry, with a confirmation step.
7. Switch between light and dark themes, and remember the choice.

### Non-functional

- No authentication or user accounts. Every visitor can perform every action.
- All API routes live under `/api`. CORS is open to any origin.
- Request bodies are validated on the server; unknown fields are rejected.
- The web app must stay usable when the API is down: it shows an explanation rather than a crash.
- API requests from the web app time out after 8 seconds.

## Data model

### Blog (MongoDB collection `blogs`, database `abu-nest-back`)

| Field | Type | Notes |
| --- | --- | --- |
| `_id` | ObjectId | Generated by MongoDB. Serialised as a 24-character hex string. |
| `title` | string | Shown on cards and as the entry heading. |
| `excerpt` | string | Short lede shown on cards and under the heading. |
| `description` | string | Full entry text. Line breaks are preserved when displayed. |
| `__v` | number | Mongoose version key. Present in responses, unused by the client. |

There are no timestamps, author, slug, or status fields.

### Validation rules

| Field | Server (`BlogDto`) | Web form (`PostForm`) |
| --- | --- | --- |
| `title` | string, not empty | 3–140 characters after trimming |
| `excerpt` | string, not empty | 10–300 characters after trimming |
| `description` | string, not empty, at least 20 characters | at least 20 characters after trimming |

The web form trims all three values before sending. The same DTO is used for create and update, so both need all three fields.

## API

Base URL: `http://localhost:4000/api`. Bodies are JSON.

### Blog object

```json
{
  "_id": "6ac339639651e4b0ca675637",
  "title": "NodeJS",
  "excerpt": "NodeJS Crash Course",
  "description": "A full entry of at least twenty characters.",
  "__v": 0
}
```

### Request body (create and update)

```json
{
  "title": "string",
  "excerpt": "string",
  "description": "string, min 20 chars"
}
```

### Endpoints

| Method | Path | Body | Success | Response body |
| --- | --- | --- | --- | --- |
| GET | `/blog` | — | 200 | `Blog[]` (empty array when there are none) |
| GET | `/blog/:id` | — | 200 | `Blog`, or `null` when no entry has that id |
| POST | `/blog` | request body | 201 | the created `Blog` |
| PATCH | `/blog/:id` | request body (all fields) | 200 | the `Blog` **as it was before the update**, or `null` when no entry has that id |
| DELETE | `/blog/:id` | — | 200 | the deleted `Blog`, or `null` when no entry has that id |
| GET | `/` | — | 200 | the text `Hello World!` |

### Errors

Validation failure, missing field, or unknown field returns 400:

```json
{
  "message": ["description must be longer than or equal to 20 characters"],
  "error": "Bad Request",
  "statusCode": 400
}
```

`message` is an array with one string per failed rule. An `:id` that is not a valid ObjectId is not handled and returns 500.

## Web features

### Routes

| Path | Purpose |
| --- | --- |
| `/` | Hero section plus the searchable index of entries |
| `/blog/new` | Create form |
| `/blog/:id` | Full entry |
| `/blog/:id/edit` | Edit form, prefilled |

Every page has a sticky header (home link, "Index", theme toggle, "New entry") and a footer.

### Index

- Entries are fetched on the server and shown as a grid of cards: 1 column on phones, 2 from `sm`, 3 from `lg`.
- Each card shows "No." plus the last 6 characters of the id in upper case, the title, the excerpt (2 lines max), the start of the description (3 lines max), and Read / Update / Delete actions.
- A counter above the grid shows how many entries are visible.
- The hero contains an interactive three.js canvas.

### Search

- Filters in the browser as the user types; no request is made.
- Matches the term, case-insensitively, against `title` and `excerpt`. `description` is not searched.
- A clear button appears when the box has text.

### Create and edit

- Both use the same form: Title, Excerpt, Entry.
- Title and Excerpt show a live character count against their limits.
- Validation runs on submit. Each invalid field shows its own message and nothing is sent.
- While saving, the submit button reads "Saving…" and both buttons are disabled.
- On success the user lands on the entry's detail page.
- If the API rejects the request, its message is shown above the buttons and the typed values stay in place.
- Cancel goes back one step in browser history.

### Delete

- Available on each card and on the detail page.
- First click swaps the button for "Delete?" with Confirm and Keep. Nothing is deleted until Confirm.
- From a card: the card disappears immediately and the list refreshes in place.
- From the detail page: the user is sent to `/`.
- On failure, the error message appears under the Delete button and the entry stays.

### Theme

- The header toggle switches between light and dark.
- The choice is stored in `localStorage` under `abu-theme` and applied before the page paints, so there is no flash of the wrong theme.
- First visit defaults to light.
- A change in one tab reaches other open tabs.

### Failure states

| Situation | What the user sees |
| --- | --- |
| API unreachable on the index | "The index did not load" panel with the reason and a hint to start the backend |
| Entry id not found, or API error, on detail or edit | "No entry at this address" page with a link to the index |
| No entries | "The index is empty" with a "Write first entry" button |
| Search with no matches | Same panel, naming the search term |
| Any route loading | Neutral pulsing placeholder |
| Unexpected render error | "This page failed to load" with a "Try again" button |

## Acceptance criteria

### API

- [ ] `GET /api/blog` returns 200 and a JSON array, `[]` when the collection is empty.
- [ ] `POST /api/blog` with a valid body returns 201 and the created entry including `_id`.
- [ ] `POST /api/blog` with an empty `title`, a missing field, or a `description` under 20 characters returns 400 with a `message` array.
- [ ] `POST /api/blog` with a field not in the DTO (for example `author`) returns 400.
- [ ] `GET /api/blog/:id` returns 200 and the entry for an existing id.
- [ ] `PATCH /api/blog/:id` with a valid full body returns 200, and a following `GET` returns the new values.
- [ ] `PATCH /api/blog/:id` with only some fields returns 400.
- [ ] `DELETE /api/blog/:id` returns 200, and the entry no longer appears in `GET /api/blog`.
- [ ] A request from a different origin succeeds (CORS).

### Web

- [ ] With the API running and entries present, `/` shows one card per entry and a matching count.
- [ ] Typing in search narrows the cards to those whose title or excerpt contains the term, in any letter case; clearing it restores all cards.
- [ ] A search with no matches shows the empty panel naming the term.
- [ ] Submitting the create form with a 2-character title shows "Title needs at least 3 characters." and sends no request.
- [ ] Submitting a valid create form opens `/blog/<new id>` showing the entered title, excerpt, and entry text with line breaks intact.
- [ ] `/blog/:id/edit` opens with the current values filled in; saving opens the detail page with the new values.
- [ ] Clicking Delete then Keep leaves the entry in place.
- [ ] Clicking Delete then Confirm on a card removes that card without a full page reload.
- [ ] Clicking Delete then Confirm on the detail page lands on `/`, and the entry is gone.
- [ ] Opening `/blog/<unknown id>` shows the "No entry at this address" page.
- [ ] With the API stopped, `/` shows "The index did not load" and the header and footer still render.
- [ ] Toggling the theme changes the page at once, and a reload keeps the chosen theme with no flash.

## Known gaps

Behaviour that exists today and that a later iteration will likely change:

- **Missing ids return 200 with `null`** on GET, PATCH, and DELETE, not 404. The web app treats `null` as not found.
- **Malformed ids return 500** (unhandled Mongoose cast error).
- **PATCH returns the old document** and requires every field; there is no partial update.
- **Server validation is looser than the form**: no maximum lengths, no minimum for title or excerpt, and no trimming, so a direct API call can store values the form would refuse.
- **Schema fields are not marked required** in Mongoose; only the DTO enforces them.
- **No pagination, sorting, or timestamps.** The index loads every entry in insertion order.
- **No authentication.**
- **Mongo connection string is hardcoded**, not configurable per environment.
- **No automated tests** in either app.
- **The index error hint says `npm run start:dev`**, but the server uses yarn.
